# P00 chore/bootstrap 새 저장소 환경 구성

- 목적: 작업 계획의 `chore/bootstrap` 브랜치(P00-01~P00-08)를 새 저장소에서 수행한다.
- 변경
  - 설계 문서 01~07, OpenAPI, 그림, AGENTS 규칙, PR 템플릿을 옮겼다. 과제 원문 PDF는 공개 저장소에 넣지 않았다. 작업 상태 기준을 `07-work-plan.md` 체크박스로 바꿨다.
  - `backend/`: Java 21, Spring Boot 3.5.16, Gradle 9.8.2, Spotless. 패키지 `com.ocs.monitoring`.
  - `frontend/`: React 19, TypeScript, Vite 7, Prettier, Vitest·Testing Library·MSW, Playwright.
  - `docker-compose.yml`: PostgreSQL 17만 둔다. `DB_PORT`로 포트를 바꿀 수 있다. 첫 기동 시 `monitoring_test`를 만든다.
  - 테스트 분리: Gradle `test`가 `test` 프로필을 켜고 `application-test.properties`가 `monitoring_test`에 접속한다.
- 실행한 명령과 결과
  - `./gradlew spotlessCheck test`: 2건 통과(`MonitoringApplicationTests`, `TestDatabaseIsolationTest`). `TEST_DB_URL`을 개발 DB로 주면 격리 테스트가 실패하는 것을 확인했다.
  - `java -jar build/libs/monitoring-0.0.1-SNAPSHOT.jar`: Spring Boot 3.5.16 기동, HikariPool이 개발 DB에 연결, `GET /` 404(엔드포인트 없음).
  - `docker compose down -v && docker compose up -d --wait db`: healthy, DB `monitoring`과 `monitoring_test` 생성 확인.
  - `npm run format:check`, `npm run build`, `npm test`(1건) 통과. Vite 개발 서버에서 화면 제목 확인.
  - `npm run test:e2e`: 1건 통과, DB 변경 테스트 1건은 `E2E_DB_CONTAINER`가 없어 건너뜀. `E2E_DB_CONTAINER=monitoring-db-1`이면 의도대로 실패.
- 판단
  - PDF 대조 결과는 [요구사항](../design/01-requirements.md#과제-기준과의-대조)에 남겼다. "상태" 필터를 심각도로 해석했다.
  - 계약 정리(P00-05): 트리 `PATH`는 펼쳐서 도달할 수 있는 하위만 근거로 한다. Pod 없는 Namespace는 경로가 없다. 405를 API 명세에 추가했다.
- 남은 문제
  - `fetchedAt`(서버 오프셋)과 `lastUpdatedAt`(UTC `Z`)의 직렬화 형식 통일 여부를 P01-07에서 정한다.
  - 문서의 `docs/report/`, `scripts/`, Flyway 파일 링크는 해당 작업에서 파일이 생기면 유효해진다.
  - E2E 임시 DB 구성은 P05-01에서 실제로 만든다. 지금은 건너뜀과 개발 DB 차단만 확인했다.
  - npm 11이 esbuild postinstall을 승인 대기로 막는다. 빌드와 개발 서버는 정상 동작했다.
