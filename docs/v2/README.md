## V2-01 검색 입력 리렌더 개선

### 스펙

- **계기:** "검색어를 입력할 때마다 화면이 계속 그려진다"는 피드백
- **문제**
  - 한 글자 입력마다 검색과 상관없는 트리, 상세 패널, 필터까지 다시 렌더링된다.
  - 검색어가 바뀌면 결과 목록이 잠깐 비었다가 다시 채워진다.
- **수락 기준**
  - 검색어를 입력하는 동안 검색 영역 밖 컴포넌트(`ResourceTree`, `ResourceDetailPanel`, `IssueLevelFilter`, `RefreshControl`)는 다시 렌더링되지 않는다.
  - 검색 응답이 오면 마지막 갱신 시각이 바뀌므로 페이지가 한 번 그려지는 것은 허용한다.
  - 검색어를 바꾸는 동안 이전 결과가 남아 있고, 새 결과가 오면 바뀐다.
  - 이전 결과를 보여 주는 동안 "검색 중" 표시가 보인다.
  - 기존 검색 동작(300ms 디바운스, 20건씩 더 보기, 필터 AND, 결과 선택 시 경로 열기)은 그대로다.
- **바꾸지 않는 것:** API 계약, ERD, 선택 상태를 페이지 한 곳에 두는 규칙

### 설계

- **원인** (아래 "결과"의 수정 전 렌더 횟수로 확인했다)
  - `useResourceSearch`를 `MonitoringPage`에서 호출해, 입력값 `input` 상태가 페이지에 있다.
  - 그래서 한 글자마다 페이지가 다시 그려지고, `useResourceTree`(`useQueries`, `branchByKey`, `viewOf`)와 하위 컴포넌트가 모두 다시 실행된다.
  - `React.memo`를 쓴 컴포넌트가 없어 중간에서 막히지 않는다.
  - 디바운스는 요청만 줄이고 렌더링은 줄이지 않는다.
  - 검색 조회에 `placeholderData: keepPreviousData`가 없어, 키가 바뀌는 순간 `data`가 빈다.
- **바꿀 내용**
  - `ResourceSearch` 안에서 `useResourceSearch(issueLevel)`를 호출한다. 페이지는 `issueLevel`, `onSelectResult`만 넘긴다.
  - 검색 조회에 `keepPreviousData`를 넣는다. Cluster 조회가 이미 같은 방식이다.
  - 이전 결과를 보여 주는 동안은 `isPlaceholderData`로 "검색 중"을 보여 주고, 빈 결과 문구는 띄우지 않는다.
- **검토한 대안**
  - 트리, 상세 컴포넌트에 `React.memo`를 붙인다: 페이지는 여전히 글자마다 다시 그려지고 `useResourceTree`도 다시 돈다. `tree` 객체와 콜백이 매번 새로 만들어져 memo가 잘 막히지도 않는다. 상태 위치를 옮기는 쪽이 원인을 없앤다.
  - 입력을 비제어(`defaultValue`)로 바꾼다: 입력값으로 결과를 다시 그리는 흐름이 복잡해진다. 상태만 아래로 내려도 충분하다.
- **영향 범위**
  - `pages/MonitoringPage.tsx`, `components/ResourceSearch.tsx`, `hooks/useResourceSearch.ts`
  - 테스트: `tests/component/search.test.tsx` (렌더 횟수, 이전 결과 유지)
  - 측정: `scripts/perf/search-input.mjs`

### 결과 (2026-11-26, main `b10db46` 기준)

- **렌더 횟수** (컴포넌트 테스트, `pod-shared` 10글자 입력부터 결과 표시까지)
  - 수정 전: 입력하는 동안 트리, 상세, 필터, 갱신 컴포넌트가 각각 10번
  - 수정 후: 입력하는 동안 0번, 응답 뒤 1번 (마지막 갱신 시각 변경)
- **입력 반응** (격리 환경, Chrome, CPU 4배 감속, 캐시 끔, 2,220행 펼침, `node-01-02`를 120ms 간격으로 입력, 3회)
  - 수정 전: 한 글자당 평균 14.1~15.2ms, 최대 46.8~55.0ms
  - 수정 후: 한 글자당 평균 5.5~6.8ms, 최대 35.2~45.9ms
  - 평균은 절반 아래로 줄었다. 최대값은 덜 줄었고, 어느 입력에서 나오는지는 따로 보지 않았다.
  - 측정 스크립트: `scripts/perf/search-input.mjs`
- **이전 결과 유지:** 검색어를 바꾸는 동안 이전 결과와 "검색 중"이 함께 보이고, 새 결과가 오면 바뀐다 (컴포넌트 테스트).
- **확인:** `npm run format:check`, `npm run build`, `npm test` 50건 (새 main 위로 옮긴 뒤), E2E 10건 (옮기기 전) 통과
- **한계**
  - 렌더 횟수는 jsdom 테스트 값이다. React DevTools Profiler로는 재지 않았다.
  - 입력 반응은 입력 이벤트부터 다음 프레임까지다. 검색 결과 표시 시간(PERF-T03)은 다시 재지 않았다.

## 쓰는 규칙

- 변경 하나는 이 문서의 섹션 하나다. 파일을 늘리지 않는다.
- 스펙에는 무엇을, 왜 바꾸는지만 쓴다. 코드 이야기는 설계에 쓴다.
- 수락 기준은 확인할 수 있게 쓴다. 측정하지 않은 값은 결과에 쓰지 않는다.
- 설계에서 ERD나 API 계약을 바꿔야 하면 멈추고 확인받는다. 결정은 [ADR](../design/02-adr.md)에 남긴다.
- 작업 문구는 커밋 메시지로 그대로 쓴다.
- 작업을 마치면 체크박스와 "진행 상태"를 함께 바꾼다.
