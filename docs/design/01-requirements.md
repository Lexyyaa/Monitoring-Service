# Infrastructure Monitoring Service 요구사항

대규모 클러스터를 운영하는 사용자가 리소스의 위치와 현재 상태를 빠르게 확인할 수 있어야 한다.

현재 데이터는 PostgreSQL에 적재한 Mock 데이터다.
Kubernetes 클러스터와 직접 연결하지 않는다.

웹 화면과 화면이 사용하는 조회 API를 함께 제공한다.

## 기능 요구사항

### 리소스 탐색

- `Cluster → Node → Namespace → Pod` 순서로 탐색한다.
- 하위 리소스는 해당 단계를 펼칠 때 조회한다.
- 화면의 Node → Namespace는 그 Node에서 실행 중인
  Pod를 기준으로 구성한다.
  - Namespace의 실제 소속은 Cluster다.
  - 같은 Namespace가 여러 Node 경로에 나타날 수 있다.

### 상태 확인

- Cluster·Node·Namespace·Pod의 이름, 상태,
  마지막 변경 시각을 확인한다.
- 리소스를 선택하면 오른쪽 상세 패널에
  해당 종류의 고유 속성과 탐색 경로를 표시한다.
- 고유 상태와 이상 심각도는 구분한다.
  - 심각도: `NONE`, `WARNING`, `ERROR`, `UNKNOWN`
  - 자식의 이상으로 부모의 고유 상태를 바꾸지 않는다.

### 검색과 필터

- 네 종류의 리소스를 이름으로 검색한다.
  열지 않은 트리 분기도 검색 대상이다.
- 검색 결과에서 리소스를 선택하면
  해당 리소스까지의 상위 경로를 연다.
- 이상 심각도로 결과를 필터링한다.
  - 검색어와 필터를 함께 쓰면 AND로 적용한다.
  - 트리에서는 직접 일치와 상위 탐색 경로를 구분한다.

### 데이터 갱신

- 30초 폴링과 수동 갱신으로 현재 표시 중인 데이터를 다시 읽는다.
- 갱신해도 검색어·필터·펼침·선택을 유지한다.
- 리소스가 필터에서 사라져도 열린 상세는 유지하고
  필터 불일치를 알린다.
- 리소스 변경 시각(`lastUpdatedAt`)과
  성공 조회 시각(`fetchedAt`)을 구분한다.

### 화면 상태

- 첫 화면, 하위 목록, 검색, 상세의
  로딩·오류·빈 결과를 구분한다.
- 한 영역의 조회가 실패하면 이전 성공 데이터를 유지한다.
  오류를 표시하고 재시도를 제공한다.

요청·응답 형식은 [API 명세](04-api-spec.md),
설계 선택 이유는 [ADR](02-adr.md)를 따른다.

## 코드 정의

화면·API·테스트에서 쓰는 코드 값과 의미다.
DB 저장 제약은 [데이터 모델](03-data-model.md), 응답 형식은 [API 명세](04-api-spec.md)를 따른다.

### 리소스 종류 · `resourceType`

| 코드 | 의미 |
| --- | --- |
| `CLUSTER` | Kubernetes 클러스터. 트리의 첫 단계 |
| `NODE` | Cluster에 속한 서버 |
| `NAMESPACE` | Cluster에 속한 논리 구역. 화면에서는 그 Namespace의 Pod가 있는 Node 아래에 표시 |
| `POD` | Node에서 실행되고 Namespace에 속한 실행 단위. 트리의 마지막 단계 |

### 이상 심각도 · `issueLevel`

| 코드 | 의미 |
| --- | --- |
| `NONE` | 이상 없음 |
| `WARNING` | 주의가 필요한 이상 |
| `ERROR` | 장애 수준의 이상 |
| `UNKNOWN` | 이상 여부를 판단할 수 없음. 데이터가 오래됐다는 뜻으로 쓰지 않음 |

- 심각도 필터의 `전체`(화면 값 `ALL`)는 필터 없음이다. API에 `issueLevel`을 보내지 않는다.
- 심각도는 리소스 자신의 값이다. 자식의 심각도로 부모의 값을 바꾸지 않는다.

### 필터 일치 역할 · `matchRole`

| 코드 | 의미 |
| --- | --- |
| `MATCH` | 리소스 자신의 심각도가 필터와 같음 |
| `PATH` | 자신은 다르지만, 아래에 필터와 같은 리소스가 있어 경로로 표시 |

- 필터가 없으면 응답에 `matchRole`이 없다.

### 고유 상태 · `statusCode`

리소스 종류마다 원천 컬럼과 값이 다르다. 심각도와 별개로 표시한다.

| 리소스 종류 | 원천 컬럼 | 값 |
| --- | --- | --- |
| `CLUSTER` | `control_plane_status` | `Ready`, `Degraded` (DB CHECK 없음, 현재 시드 값) |
| `NODE` | `ready_condition` | `True`, `False`, `Unknown` |
| `NAMESPACE` | `phase` | `Active`, `Terminating` |
| `POD` | `phase` | `Pending`, `Running`, `Succeeded`, `Failed`, `Unknown` |

### 오류 코드 · `code`

| 코드 | HTTP 상태 | 의미 | 안내 문구 |
| --- | --- | --- | --- |
| `INVALID_PARAMETER` | 400 | 잘못된 ID·종류·심각도·검색어·페이지·`nodeId` | 요청 파라미터를 확인해 주세요. |
| `RESOURCE_NOT_FOUND` | 404 | 없는 리소스 또는 잘못된 상하위 경로 | 해당 리소스 또는 경로를 찾을 수 없습니다. |
| `METHOD_NOT_ALLOWED` | 405 | 조회(GET) 외의 HTTP 메서드 | 지원하지 않는 HTTP 메서드입니다. |
| `INTERNAL_ERROR` | 500 | 예상하지 못한 서버 오류. 내부 정보는 응답하지 않음 | 요청을 처리하지 못했습니다. |
| `SERVICE_UNAVAILABLE` | 503 | DB 등 조회에 필요한 서비스를 일시적으로 쓸 수 없음 | 데이터를 일시적으로 조회할 수 없습니다. |

## 비기능 요구사항

### 데이터 규모

- Cluster 20개
- Node 200개
- Namespace 2,000개
- Pod 100,000개 이상

전체 Pod를 매 요청마다 Java 메모리로 읽어 순회하지 않는다.
대량 리소스를 한 번에 DOM에 그리지 않는다.

### 화면 성능 목표

Chrome 최신 버전에서 CPU 4x throttling과
캐시 비활성화 조건으로 측정한다.

- 첫 Cluster 표시·상호작용: 500ms 이내
- 트리 펼침·접힘 반응: 100ms 이내
- 검색 결과 표시: 디바운스 제외 300ms 이내
- 필터 반영: 200ms 이내
- 대량 목록 스크롤: Performance FPS 미터 기준 55fps 이상
- 데이터 갱신: 전체 깜빡임 없이 변경 부분 200ms 이내
- 탭 메모리: Chrome 작업관리자 기준 참고 목표 300MB 이하
  - 초과 시 원인과 개선 방향을 기록한다.

실제 측정 결과는
[브라우저 성능 결과](../report/02-browser-performance.md)에 있다.

## 현재 서비스 범위

- 제공: 저장된 Mock 데이터의 탐색·검색·상세·필터·갱신
- 제공하지 않음:
  - Kubernetes·GPU·CI/CD 환경의 직접 수집
  - 이상 판정 엔진, 이력·차트·로그, 알림·복구
  - 로그인·권한, 하위 상태별 개수 집계

## 과제 기준과의 대조

과제 원문(공개 저장소에 포함하지 않음)과 이 문서를 대조한 결과다. 계약은 바꾸지 않았다.

| 항목 | 과제 기준 | 이 문서 | 판단 |
| --- | --- | --- | --- |
| 계층 | Cluster → Node → Namespace → Pod 드릴다운 | 같은 순서. Namespace의 실제 소속은 Cluster | 일치. 화면 경로는 Pod 관계로 도출([ADR-001](02-adr.md)) |
| 규모 | Cluster 20, Node 200(Cluster당 10), Namespace 2,000(Node당 10), Pod 10만 이상(Namespace당 50) | 같은 총량 | 일치. Node당 Namespace 10개 배치는 시드에서 맞춘다(P01-04) |
| 표시 정보 | 이름, 상태, 마지막 갱신 시간, 종류별 추가 정보 | 이름, 고유 상태, 심각도, `lastUpdatedAt`, 종류별 속성 | 일치 |
| 렌더링 | 10만 건을 한 번에 DOM에 그리지 않음 | 대량 리소스를 한 번에 그리지 않음 | 일치 |
| 탐색 | 트리, 필요 시점 로드 | 펼칠 때 조회 | 일치 |
| 선택 | 상세 정보 확인 | 오른쪽 상세 패널 | 일치 |
| 검색 | 이름 검색, 계층 내 위치 표시 | 열지 않은 분기 포함 검색, 상위 경로 열기 | 일치 |
| 필터 | 상태(정상/경고/오류 등) | 이상 심각도 `NONE`·`WARNING`·`ERROR`·`UNKNOWN` | 해석 차이. 과제의 "상태"를 심각도로 대응하고 고유 상태와 분리했다 |
| 갱신 | 새로고침·폴링·스트리밍 중 선택과 이유 | 30초 폴링과 수동 갱신 | 일치. 이유는 [ADR-002](02-adr.md) |
| 데이터 | Mock, 생성 스크립트와 저장소 분리 허용 | 시드 SQL로 PostgreSQL에 적재 | 일치 |
| 성능 목표 7개 | 측정 조건 포함 | 같은 값과 조건 | 일치 |
| 제출물 | 소스, README 8개 항목, 추가 기능과 이유 | 이 문서 범위 밖 | README는 P05-11에서 항목을 맞춘다 |

확인할 점:

- 스크롤 목표는 "10만 건 규모 리스트" 기준이다. 측정 행 수와 조건을 성능 기록에 밝힌다(P05-07).
- 과제의 "상태" 필터를 심각도로 해석한 근거는 README에도 적는다.
